# 微服务架构设计要点

本文档描述微服务架构设计中的核心要点，供研发团队参考。

## 一、服务拆分原则

微服务架构的第一步是合理的服务拆分。建议按业务领域（Domain）拆分，遵循单一职责原则。每个服务拥有独立的数据库，避免跨服务事务。

## 二、服务间通信

服务间通信推荐采用同步 REST 或异步消息（如 Redis Streams、Kafka）。同步调用用于实时查询，异步消息用于解耦长任务。

## 三、服务发现与网关

采用注册中心实现服务发现，API 网关统一入口，负责鉴权、限流、路由转发。网关与注册中心配合可实现服务实例的优雅上下线。

## 四、配置中心

配置集中管理，支持动态刷新。环境隔离（dev/test/prod）通过配置中心命名空间实现。

## 五、可观测性

每个服务必须输出日志、指标（Metrics）与链路追踪（Tracing）三类可观测数据。日志采用结构化格式，指标暴露 Prometheus 端点，追踪对接 Jaeger。

## 六、容错与弹性

采用熔断、降级、重试、限流等容错手段。熔断器防止故障扩散，降级策略保证核心链路可用。

## 七、部署与发布

微服务采用容器化部署（Docker），通过编排平台（Kubernetes）管理。发布采用滚动更新与金丝雀发布，保证灰度验证。

## 八、团队组织

微服务团队按业务域组建（康威定律），每个团队负责对应服务的开发与运维，实行 DevOps 文化。
