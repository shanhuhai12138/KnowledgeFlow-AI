## 0. 决策记录（DR）

| # | 决策项 | 结论 | 理由 |
|---|--------|------|------|
| DR-1 | AI 编排层 | **混合架构：Java 后端 + Python FastAPI + LangGraph** | LangGraph 是有状态图编排（循环/分支/checkpointer/human-in-the-loop），业界主流；Java 侧无等价物 |
| DR-2 | 脚手架 | **基于 RuoYi-Vue-Pro 改造**（认证/RBAC/代码生成器复用） | 团队已有若依体系经验，基建期从 2 周压到 1 周 |
| DR-3 | 前端构建方式 | **HTML 原型先行**（ojo 生成高保真原型）→ 用户确认 → Vue 3 重构 | 设计稿即方针，避免前后端字段/交互返工 |
| DR-4 | 前端总风格 | **A. 编辑社论风（Editorial）**，允许适度花哨 | 不重 AI 感、配色高级（暖白×墨黑×朱红）、答辩辨识度高 |
| DR-5 | 向量数据库 | **Qdrant**（Docker 独立服务） | 专业向量库、本地免费、过滤/混合检索能力强 |
| DR-6 | 业务数据库 | **MySQL**（沿用若依默认） | 向量已独立到 Qdrant，无需引入 pgvector 换库 |
| DR-7 | 异步任务 | **Redis Streams** | 复用已有 Redis，轻量够用，不上 Kafka |
| DR-8 | 文件存储 | **MinIO**（S3 兼容） | 文档文件对象化存储，可替换任意 S3 |
| DR-9 | regent 项目 | **本地 regent 副本作实现参考**（[shanhuhai12138/regent](https://github.com/shanhuhai12138/regent)） | 不直接继承代码，LangGraph + Qdrant 重写，架构保持干净 |
| DR-10 | 架构形态 | **模块化单体**（Java 单服务 + Python 单服务） | 简单可部署，答辩可讲清模块边界，不拆微服务 |
| DR-12 | LLM / Embedding | **LLM = DeepSeek**（`deepseek-chat`，OpenAI 兼容）；**Embedding = 本地 BGE-M3**（DeepSeek 无 embedding API，BGE 免费离线中文强） | 国内直连、成本低；适配层隔离可切换 |
| DR-13 | 开源与 API Key 管理 | **开源到 GitHub**，部署者在**前端设置页填写自己的 API Key**（后端 AES 加密存库 → 调 Python 时请求头注入）；环境变量作 fallback | 别人开箱即用，不用改代码；key 不落 git |

## 1. 项目概述

**定位**：企业级知识管理 + RAG 智能问答 + Agent 工作流平台。用户上传文档后系统自动分块向量化，可对知识库进行语义检索、多轮问答（答案带引用来源与置信度），并支持 LangGraph 编排的多步骤智能体任务。

**产品定位（DR-11）**：**通用空壳平台 + 内置演示知识库**。架构上支持任意团队建库/上传/多租户（通用空壳），内置一个「软件开发团队知识库」演示库实现开箱即演示；种子数据可整体替换为任意行业内容，快速转向垂直场景。答辩叙事：*"平台能力通用，预置演示库展示开箱体验，换种子数据即可转向垂直行业。"*

**目标**：
- 完成度高的可演示系统（登录 → 上传 → 检索 → 问答 → 引用 → 看板全链路闭环）
- 技术栈扎实：Spring Boot 3 + Vue 3 + FastAPI + LangGraph + Qdrant + Redis Streams
- 前端有设计辨识度（编辑社论风），答辩可讲"AI 编排（Python）+ 业务（Java）"的语言分工架构

**MVP 核心闭环**（一切功能的裁剪基准）：
```
登录 → 上传文档 → 异步分块+向量化 → 语义检索 → LLM 流式问答（带引用）→ 分析看板
```
除闭环五件事之外的任何功能（多知识库、版本历史、成员管理、导出报表……）都按 P1/P2 弹性裁剪。

### 2.3 种子演示数据（内置演示知识库）

- **定位**：通用空壳架构不变，内置一个演示知识库实现开箱即演示（DR-11）
- **题材**：软件开发团队知识库，预置文档示例：
  - 《开发环境搭建 SOP.md》
  - 《代码规范与评审流程.pdf》
  - 《微服务架构设计文档.docx》
  - 《故障排查 FAQ.txt》
  - 《季度技术复盘.md》
- **作用**：登录即有内容可问、可演示引用来源与置信度；演示不依赖现场上传文档
- **实现**：seed 脚本三件套——MySQL 初始化 SQL（知识库/文档记录）+ MinIO 预置文件 + Qdrant 预构建向量索引（首次启动自动检测，空库时灌入）
- **扩展性**：种子数据集中于 `deploy/seed/` 目录，整体替换即可转向任意垂直行业

### 2.2 非功能需求

| 编号 | 要求 | 目标 |
|------|------|------|
| NFR-1 | 检索延迟 | 语义检索 < 500ms，问答首字 < 2s |
| NFR-2 | 文档处理 | 100 页 PDF 处理 < 3min（异步，不阻塞请求） |
| NFR-3 | 安全 | 密码 BCrypt、JWT 无状态、RBAC 越权拦截、文件类型白名单、输入校验 |
| NFR-4 | 可部署性 | Docker Compose 一键启动（mysql/redis/minio/qdrant/backend/ai/frontend/nginx） |
| NFR-5 | 无障碍 | 文本对比度 ≥ 4.5:1、键盘可操作、焦点可见（遵循 design-system skill 规范） |

## 3. 系统架构

```
┌────────────────────────────────────────────────────────────┐
│  Vue 3 前端（RuoYi 前端改造 + 按 HTML 原型定制，编辑社论风） │
│        │  REST / SSE（流式）                                │
│        ▼                                                    │
│  Spring Boot 3 后端（RuoYi-Vue-Pro 基座）                   │
│  ├─ 复用：JWT 认证、RBAC、代码生成器、系统管理、定时任务     │
│  ├─ 新增：知识库模块、文档模块、统计接口                    │
│  │        │  HTTP（REST / SSE）                             │
│  │        ▼                                                 │
│  Python AI 编排服务（FastAPI + LangGraph）                  │
│  ├─ 检索链：分块 → embedding → Qdrant → 重排序 → 生成       │
│  ├─ Agent：多步工作流、循环、human-in-the-loop              │
│  └─ LLM 适配层：OpenAI / 本地模型可切换                     │
└────────────────────────────────────────────────────────────┘
        ▼
  MySQL（业务数据）   Qdrant（向量）   Redis + Streams（缓存/异步）
  MinIO（文档文件）    LLM API（OpenAI / 本地）
```

### 3.1 职责边界（关键约定）

| 端 | 负责 | 不负责 |
|----|------|--------|
| Java 后端 | 用户/权限、知识库、文档 CRUD、上传下载、搜索/统计 API、异步任务投递 | 不做向量检索细节、不直接调 LLM |
| Python 服务 | 文档解析分块、embedding、Qdrant 读写、检索重排、LangGraph 编排、LLM 调用 | 不做业务 CRUD；无状态服务，仅暴露 AI 能力接口 |
| 通信协议 | Java ↔ Python 走 HTTP：同步 REST + SSE 流式；长任务（文档处理）由 Java 侧 Redis Streams 驱动 | — |

> 理由：Java 保持"纯后端管理"，AI 收敛到 Python 侧，答辩可清晰讲"模块化 + 语言分工"；真实企业普遍采用此架构。

## 6. 数据模型（核心表）

> 实现说明（T2.2/T2.3/T7 落地）：在下列表结构基础上补充若依多租户支撑列——`tenant_id`（多租户隔离，框架 TenantLineHandler 自动过滤，登录需带 `tenant-id` header）、`creator/updater/deleted`（BaseDO 标准审计列，逻辑删除）。实际 DDL 见 `deploy/seed/mysql-init/`（01-kb-tables.sql、02-document-tables.sql、03-query-log-table.sql、05-demo-kb.sql、06-ai-config-table.sql）。

```sql
-- 知识库
CREATE TABLE kb_knowledge_base (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(255) NOT NULL,
  description TEXT,
  is_private TINYINT(1) DEFAULT 1,
  owner_id BIGINT NOT NULL,
  document_count INT DEFAULT 0,
  member_count INT DEFAULT 0,
  created_at DATETIME, updated_at DATETIME
);

-- 知识库成员（角色：ADMIN / EDITOR / VIEWER）
CREATE TABLE kb_member (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  kb_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  role VARCHAR(20) NOT NULL,
  created_at DATETIME,
  UNIQUE KEY uk_kb_user (kb_id, user_id)
);

-- 文档
CREATE TABLE kb_document (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  kb_id BIGINT NOT NULL,
  uploader_id BIGINT NOT NULL,
  filename VARCHAR(500) NOT NULL,
  object_name VARCHAR(1000) NOT NULL,   -- MinIO 对象键
  file_type VARCHAR(10) NOT NULL,       -- pdf/docx/txt/md
  file_size BIGINT,
  page_count INT,
  status VARCHAR(20) DEFAULT 'pending', -- pending/processing/processed/failed
  tags VARCHAR(1000),                   -- 逗号分隔
  chunk_count INT DEFAULT 0,
  version INT DEFAULT 1,
  created_at DATETIME, updated_at DATETIME,
  KEY idx_kb_id (kb_id), KEY idx_status (status)
);

-- 文档版本历史
CREATE TABLE kb_document_version (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  document_id BIGINT NOT NULL,
  object_name VARCHAR(1000) NOT NULL,
  file_size BIGINT,
  content_hash VARCHAR(64),
  version INT NOT NULL,
  created_by BIGINT, created_at DATETIME
);

-- 会话与消息（问答）
CREATE TABLE kb_chat_session (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id BIGINT NOT NULL,
  kb_id BIGINT,
  title VARCHAR(255),
  created_at DATETIME, updated_at DATETIME
);
CREATE TABLE kb_chat_message (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  session_id BIGINT NOT NULL,
  role VARCHAR(10) NOT NULL,            -- user/assistant
  content LONGTEXT NOT NULL,
  sources JSON,                         -- [{documentId, documentName, page, score}]
  confidence DECIMAL(3,2),
  rating VARCHAR(10),                   -- up/down/null
  created_at DATETIME
);

-- 统计
CREATE TABLE kb_query_log (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id BIGINT, kb_id BIGINT,
  query_text VARCHAR(500),
  took_ms INT, hit_count INT,
  created_at DATETIME
);

-- Qdrant 侧（向量元数据点）：id = 文档 chunk 唯一键
-- payload: { documentId, chunkIndex, content, page, kbId, filename }
```

> 约定：Qdrant 中每条向量 payload 带 `kbId`，检索时按 `kbId` 过滤实现知识库隔离；删文档时按 `documentId` 删除对应点。

|------|------|------|
| 大标题/品牌（衬线，海报张力） | **Noto Serif SC**（中文）+ **Playfair Display**（英文/数字） | 加粗 600-900，`letter-spacing: -0.02em` |
| 正文/界面 | **Inter**（数字/英文）+ 系统黑体（PingFang SC / Microsoft YaHei） | 14-16px，行高 1.6 |
| 数据/表格 | Inter 数字特性 `font-variant-numeric: tabular-nums` | 对齐稳定 |

字号阶梯（Major Third 1.25）：12 / 14 / 16 / 20 / 25 / 31 / 39 / 48px。

### 7.3 视觉语言

- **配色纪律**：全站黑白灰 + 单一朱红强调色；**禁止**紫蓝渐变、霓虹发光、玻璃拟态大面积滥用（这是"反 AI 感"门禁，沿用 zip 里 theme-guide 的 anti-pattern 思想）
- **版面**：杂志式网格——数据密集页（文档/看板）用细线分隔 + 表格线；登录/Chat 用编辑排版（大标题、引导语、pull-quote 式引用块）
- **圆角**：克制（按钮/输入 6px、卡片 10px），不做大圆角泡泡感
- **分隔**：1px `--line` 细线 + 留白（8px 节奏）建立层级，少用阴影、多用线条与空间
- **图标**：统一 2px 描边线性图标（Element Plus 图标 / Lucide 风格），不混用 emoji

### 7.4 动效（允许花哨，但有纪律）

| 场景 | 规格 |
|------|------|
| 微交互 | 150-300ms，`ease-out`；hover 卡片微升 `translateY(-2px)` + 阴影增强 |
| 流式问答 | 打字机逐字输出（`steps(1, end)` 渐显），输入区"思考中…"三点动画 |
| 页面切换 | 淡入 + 8px 上移，150-200ms；列表项交错入场 30-50ms stagger |
| 装饰性 | 登录页品牌区允许克制的衬线大字与几何点缀动效（低饱和、不抢内容） |
| 纪律 | `prefers-reduced-motion` 时全部关闭；一屏最多 1-2 个主动画 |

### 7.5 各页风格要点

- **登录页**：左品牌区——暖白纸面 + 超大衬线标题"让企业知识开口说话" + 朱红细线；右表单区——白卡 + 细线框输入
- **聊天页**：用户气泡墨黑底白字（海报感强）；AI 卡片白底 + 1px 细线 + 左上角衬线小标"AI 答复"；来源卡片朱红页码角标
- **文档页**：表格细线（`border-collapse` + 1px line），状态用文字+朱红/绿小圆点（不只靠颜色）
- **看板页**：图表用 **lieflat-charts** 单色模板（墨黑/朱红单色系），统计卡大数字 + tabular-nums

## 9. API 契约约定（前后端 + Java↔Python 对齐）

- 统一响应体：`{ code, message, data }`
- 字段命名：全 camelCase（如 `fileType`、`pageCount`、`knowledgeBaseId`）
- 时间：**毫秒时间戳**（Long，如 `1785572108777`；由前端 dayjs 统一转换为展示格式。若依框架默认行为，契约以此为准）
- 分页：`page`（1 起）/ `size`
- **HTML 原型的 MOCK 字段即为后端 DTO 字段基准**：原型确认后，Java DTO / Python Pydantic 模型按原型字段抄写
- 关键 DTO（已由原型定义）：
  - `Document { id, kbId, kbName, filename, fileType, fileSize, pageCount, status, uploader, tags[], createdAt, updatedAt }`
  - `KnowledgeBase { id, name, description, isPrivate, documentCount, memberCount, createdAt, updatedAt }`
  - `Message { id, role, content, sources[{documentId, documentName, page, score}], confidence, rating, createdAt }`
