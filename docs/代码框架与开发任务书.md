【验收】Swagger 可测全部接口；数据落库正确

### T2.3 文档模块（document-module）
【目标】文档 CRUD + MinIO 上传下载 + 元数据
【输入】项目书 §6 表 `kb_document` / `kb_document_version`；原型文档页
【产出】上传（multipart）→ 存 MinIO → 落库（status=pending）→ 向 Redis Stream `doc-pipeline` 投递处理消息
【字段契约】`Document { id, kbId, kbName, filename, fileType, fileSize(Long), pageCount, status, uploader, tags[], createdAt, updatedAt }`
【验收】上传 PDF 后 MinIO 可见对象、DB 记录 status=pending、Stream 有消息；文档列表/筛选/批量删除接口可用

### T2.4 搜索与问答 API（search-module）
【目标】统一入口，转发 Python AI 服务
【规格】
- `POST /api/search` → 转发 `ai-service /ai/search`
- `POST /api/chat` + `GET /api/chat/stream`（SSE）→ 转发 `/ai/chat` `/ai/chat/stream`
- 查询日志落 `kb_query_log` 表
【字段契约】`Message { id, role, content, sources[{documentId, documentName, page, score}], confidence, rating, createdAt }`
【验收】Python 服务未起时返回 503 + 明确错误信息；起来后链路通
【附加任务（T2.3 验收时发现）】`DocumentRespVO.uploader` 目前返回用户 ID（如 `"1"`），与原型"张伟"式显示名不一致：改为联查用户表返回 `username`，文档列表"上传者"列与原型对齐

### T2.5 文档处理流水线（pipeline-module）
【目标】Redis Streams 消费者：收到 `doc-pipeline` 消息 → 调 Python `/ai/ingest` → 回写状态
【规格】状态流转 `pending → processing → processed/failed`；失败重试 3 次；处理中允许查询处理状态
【验收】上传文档后状态自动流转到 processed（Python 侧已实现时）

【Streams 消息契约（doc-pipeline）】
- Stream key：`doc-pipeline`；消费者组：`doc-pipeline-group`，消费者：`ingest-consumer`
- 消息字段（field-value 扁平，全部字符串）：
  - `documentId`：文档 ID
  - `kbId`：知识库 ID
  - `objectName`：MinIO 对象键
  - `filename`：文件名
  - `attempt`：尝试次数（首次 `1`）
- 流程：
  1. 生产者（T2.3 上传成功后）：`XADD doc-pipeline * documentId d1 kbId kb1 ... attempt 1`
  2. 消费者：`XREADGROUP GROUP doc-pipeline-group ingest-consumer` → 调 `POST /ai/ingest` → 成功则 `XACK` + 更新文档 `status=processed` + 回填 chunkCount
  3. 失败：`attempt+1` 重新入队（XPENDING 待确认，延迟重试）；`attempt > 3` → `status=failed` + `XACK`（死信，记录 error 字段）
- 幂等：`/ai/ingest` 以 documentId 幂等（Qdrant 先删该 documentId 全部点再写入）；重复消息安全

## 5. 任务 T4：AI 服务（`ai-service/`，FastAPI + LangGraph）

> 参考实现：本地 regent 副本（[shanhuhai12138/regent](https://github.com/shanhuhai12138/regent)），Python RAG 实现可借鉴分块/检索逻辑

### T4.0 接口契约（Java ↔ Python HTTP）

【模型适配（DR：LLM=DeepSeek）】
- **LLM**：DeepSeek `deepseek-chat`，OpenAI 兼容 API（`base_url=https://api.deepseek.com`，key 走环境变量 `DEEPSEEK_API_KEY`，不进代码库）
- **Embedding**：⚠️ **DeepSeek 目前无 embedding API** → 用本地 **BGE-M3**（`sentence-transformers`，中文检索强、免费离线、无需外网）；config 用 `embedding.provider=bge-local` 隔离，后续可切换
- 适配层：LLM 与 embedding 均做成 provider 接口（参考 regent 抽象层设计），换模型只改 config

> 统一约定：`Content-Type: application/json`；FastAPI 默认错误体 `{"detail": "..."}`；前端/后端只依赖本契约，禁止隐式依赖 Python 内部实现。

#### `POST /ai/ingest`
请求：`{ "documentId": "d1", "kbId": "kb1", "filename": "xx.pdf", "fileType": "pdf", "content": "文档全文文本" }`
响应 200：`{ "documentId": "d1", "chunkCount": 12, "vectorCount": 12 }`
错误：422（缺字段）/ 413（内容过大）/ 500（业务失败，含 detail）
幂等：同 documentId 重复调用 → 先删旧向量再写

#### `DELETE /ai/documents/{documentId}`（T2.3 补充，文档删除一致性）
删除该 documentId 的全部向量点（Java 删除文档时同步调用，尽力而为）。
响应 200：`{ "documentId": "d1", "deleted": true }`；404（collection 不存在等）

#### `POST /ai/search`
请求：`{ "query": "...", "kbId": "kb1", "topK": 5, "threshold": 0.6, "useHybrid": true }`
响应：`{ "query": "...", "tookMs": 45, "results": [ { "documentId": "d1", "documentName": "...", "page": 24, "score": 95, "content": "chunk 文本" } ] }`
说明：`useHybrid=false` 仅 dense；`true` 走 RRF 融合（借鉴 regent fusion.py）

#### `POST /ai/chat`
请求：`{ "sessionId": "s1", "kbId": "kb1", "message": "...", "history": [ {"role":"user","content":"..."}, {"role":"assistant","content":"..."} ] }`
响应（Message 契约）：`{ "id": "a123", "role": "assistant", "content": "...", "sources": [...], "confidence": 88, "rating": null, "createdAt": "2026-07-31T10:30:00" }`

#### `GET /ai/chat/stream?sessionId=&kbId=&message=`（SSE）
事件流（`text/event-stream`）：
```
event: meta     data: {"type":"meta","sessionId":"s1","message":"..."}
event: content  data: {"type":"content","delta":"逐步文本"}      # 可多次，前端打字机拼接
event: sources  data: {"type":"sources","sources":[{...}],"confidence":88}
event: done     data: {"type":"done","messageId":"a123"}
event: error    data: {"type":"error","message":"..."}
```
前端按原型逻辑：content 事件逐字/逐段渲染，sources 事件渲染引用卡片。

#### `GET /ai/agent/...`（T4.4 定义，先占位）

### T4.1 骨架
【产出】`main.py`（CORS、路由挂载）、`config.py`（模型/Qdrant/密钥，环境变量驱动）、`routers/`（ingest、search、chat、agent）

【验收】`uvicorn main:app` 启动，`/docs` 可开

### T4.2 RAG 链路（参考 regent）
【规格】
- `POST /ai/ingest`：接收 { documentId, filename, content } → 分块（中文感知，参考 regent `chunker`）→ embedding → 写入 Qdrant（payload 含 `documentId/kbId/page`）
- `POST /ai/search`：query → embedding → Qdrant 按 `kbId` 过滤检索 Top-K → 返回 `[{documentId, documentName, page, score, content}]`
【验收】curl 上传一段文本后可检索到

【regent 参考实现要点（从 regent 副本提炼，直接采用/借鉴）】
1. **分块器**（`src/libs/splitter/recursive_splitter.py`）：分隔符优先级 `["\n\n", "\n", "。", "，", " ", ""]` —— **中文感知**，比纯字符切块质量高，直接采用；默认 `chunk_size=1000` / `overlap=200`；`chunk_id = md5(text)[:12]`；记录 `start_offset/end_offset` 便于回映射原文
2. **混合检索**（`src/core/query_engine/hybrid_search.py` + `fusion.py`）：Dense + Sparse 双路 + **优雅降级**（一路失败自动用另一路）；RRF 融合 `score = Σ 1/(k + rank + 1)`（k 默认 60）；n-gram Jaccard 去重（阈值 0.85）后截断 top_k。我们落地：Qdrant dense + Qdrant 全文近似 sparse，融合逻辑照搬 RRF + 去重
3. **摄取流水线**（`src/ingestion/pipeline.py`）：阶段化（加载→切块→编码→入库），每阶段独立 try/except 并记录 stages 状态 —— 对应我们的 status 流转；`asyncio.Semaphore(2)` 并发限流；Dense 失败降级不阻塞全流程
4. **抽象层设计**：loader / splitter / embedding / vector_store / llm 均为可替换接口 —— 我们按同样方式抽象，vector_store 实现 Qdrant 版即可
5. **Agent 工作流**（`src/ragent_backend/workflow.py` + `intent.py`）：意图识别 + 多步工作流 + 记忆管理，T4.4 可参考其图结构与 human-in-the-loop 挂点

【删除联动（必做，正确性问题）】用户删除文档（T2.3 DELETE）时，Qdrant 中该 documentId 的向量会成**孤儿** → 检索仍命中已删文档。方案：
  a. **推荐**：Java 删除文档时同步调 Python `DELETE /ai/vector?documentId=` 删点（T4.2 实现此路由）
  b. 备选：检索后按 DB 存活文档过滤（开销大，不推荐）
采用 a。验收：删除文档后 `/ai/search` 不再返回其内容

### T4.4 Agent 工作流（LangGraph）
【规格】问答图（检索→生成→验证）；可选多步 Agent 图（循环/分支/human-in-the-loop，先实现一个演示场景如"文档分析"：检索→摘要→分类→生成报告）
【验收】`/ai/agent` 可执行并返回步骤记录
【实现确认（T4.4 已交付，验收 11/11）】图结构 `retrieve → summarize → classify → report_gate(human-in-the-loop) → report`，空检索走 `not_found` 分支；接口：

| T6.1 Stream 修剪 | `doc-pipeline` 只 XACK 不移除，Stream 无限增长 | 定时 `XTRIM MAXLEN ~2000`（@Scheduled 每日一次） |

| T6.4 文档版本保留 | `kb_document_version` 每版本一条，无限增长 | 保留最近 N=5 版本，超限清理（可配置） |
| T6.5 孤儿向量兜底（可选） | 删除联动万一失败 | 低频定时校验：Qdrant 中 documentId 不在 DB → 清理 |
