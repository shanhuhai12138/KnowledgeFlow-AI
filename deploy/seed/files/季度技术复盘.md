# 季度技术复盘

> 本季度团队技术工作总结：成果回顾、问题反思与下季度改进计划。供团队成员与管理者阅读。

## 1. 本季度成果

### 1.1 核心项目交付

- **KnowledgeFlow AI 平台**完成从零到一的搭建：企业知识管理与 RAG 智能问答平台。
- 打通核心闭环：文档上传 → 异步分块向量化 → 语义检索 → 流式问答（带引用与置信度）→ 分析看板。
- 全链路真实可演示，不依赖 mock 数据。

### 1.2 技术体系沉淀

- **后端**：基于 RuoYi-Vue-Pro（Spring Boot 3）扩展知识库、文档、搜索、流水线模块，多租户隔离。
- **AI 编排**：FastAPI + LangGraph，实现文档处理、混合检索、流式问答与 Agent 工作流（human-in-the-loop）。
- **前端**：Vue 3 + Element Plus，编辑社论风视觉体系（墨黑 × 暖白 × 朱红）。
- **基础设施**：Docker Compose 一键编排 MySQL / Redis / MinIO / Qdrant。

### 1.3 工程化改进

- 建立统一 API 契约文档（camelCase 字段、SSE 事件序列），前后端并行开发零返工。
- 验收脚本体系：每个模块配自动化验收脚本（`docs/verify/`），可复跑。
- 关键经验沉淀为团队记忆库：Windows 终端编码坑、服务重启流程、端口映射约定。

## 2. 存在的问题

### 2.1 技术层面

- **Embedding 语义质量受限**：本地降级向量为字面特征匹配，同义改写检索效果一般；已预留 OpenAI/BGE 切换能力，需接入真模型提升语义召回。
- **文档解析覆盖不足**：目前支持 PDF/DOCX/MD/TXT，扫描版 PDF（图片型）无法提取文字，需要 OCR 能力。
- **并发处理**：Redis Streams 消费者为单线程，大文件批量上传时处理吞吐受限。
- **Agent 工作流**：human-in-the-loop 为演示级实现，生产级需结合持久化存储与超时告警。

### 2.2 协作层面

- 前期接口契约冻结不及时，出现过一次字段命名返工。
- 演示环境与开发环境配置混用，偶尔出现"本机能跑、别人机器跑不起来"。
- 文档沉淀滞后，部分排查经验只存在于个人记忆中。

## 3. 下季度改进计划

### 3.1 检索质量提升（P0）

1. 接入 BGE-M3 本地模型或 OpenAI Embedding，重建索引并评估召回率。
2. 实现混合检索（向量 + 关键词 RRF 融合）与重排序，提升检索精度。
3. 增加查询日志分析：低频命中词自动预警，反哺文档完善。

### 3.2 平台能力增强（P1）

1. 文档处理流水线水平扩展：消费者多线程 + 失败死信队列可视化。
2. 支持更多文档格式：Excel、PPT、扫描版 PDF（OCR）。
3. 知识库导入导出：批量迁移与备份恢复。

### 3.3 工程与质量（P1）

1. 补充单元测试与集成测试（Testcontainers），核心模块覆盖率目标 60%。
2. 环境一致性：统一 Docker 开发环境，消灭"本机能跑"问题。
3. 完善可观测性：接入指标采集与告警，LLM Token 消耗看板。

### 3.4 演示与答辩（P0）

1. 完善演示脚本与录屏（3-5 分钟全链路）。
2. 准备常见答辩问题答案（架构分工、技术选型理由、难点与解决）。
3. 种子数据持续打磨：让演示库内容更贴近真实业务。

## 4. 团队文化建议

- **复盘常态化**：每双周一次轻量复盘，只谈问题与改进，不追责。
- **知识库优先**：任何踩过的坑，当天沉淀到团队知识库（就用我们自己的平台）。
- **评审文化**：代码评审不是形式，是团队成长的加速器。

> 复盘的目的不是回顾过去，而是让下一个季度做得更好。共勉。
